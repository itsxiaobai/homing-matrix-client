# design/ — UI/UX 設計接收軌道（給人類的說明，人類可隨時改寫）

> 用途：您把視覺／互動設計放進本目錄，Agent（GLM，下稱 Agent）按此實作。
> 一律遵循 AGENTS.md：**最終介面由人類設計**；Agent 不得自定配色、字型、圖示、
> logo、間距、動效，也不得仿造任何品牌識別（含 LINE）。

## 目錄結構

```
design/
├── README.md          ← 本檔（流程說明；您可改寫）
├── tokens.md          ← 全局設計 Token（最優先填；填完後任何頁面都吃它）
└── pages/
    ├── _template.md   ← 每頁必答清單模板（複製一份 → 改名成頁名再填）
    └── <頁名>.md＋同名的圖（可選）
```

## 交付層級（由粗到細；給到第 3 層即可 1:1 實作）

| 層 | 形式 | 放哪 |
|---|---|---|
| 1 結構 | 手繪／白板照／純文字說明 | `pages/<頁名>.md` 內含或附圖 |
| 2 版面 | 截圖／figma／手繪標註（相對位置即可，不必精確像素） | 同上 |
| 3 規格 | **文字標註**（每頁必答清單） | 同上 |
| 4 Token | 色票／字型／圓角／間距／圖示 清單 | `tokens.md` |

## 每頁必答清單（複製 `pages/_template.md` 填寫）

```
畫面：＿＿＿＿
元素：…（有什麼列什麼）
按鈕：每個 → 按下行為；disabled／按下／載入中長相（省略＝沿用現狀草案）
狀態：空狀態／載入中／錯誤 長相（省略＝沿用現狀草案）
深淺：淺＋深各一份？或僅淺色？
不動：若整頁沿用現狀，寫「這頁不動」四字即可
```

## Agent 的處理流程（每步有您的確認點）

1. 收到 `design/` 更新 → Agent 回覆 **3–5 行**：會動哪些檔案、哪些行為會跟著變、
   是否觸及停機條件 → **等您確認才動手**（AGENTS.md 慣例）。
2. 實作：樣式集中到 `lib/ui/design_tokens.dart`（唯一翻譯源；業務代碼不出現
   魔法色值／寫死間距）；`flutter analyze` / `flutter test` 必須全綠
   （+121 為行為鎖，證明換皮不換功能）。
3. 出 APK → 您實機驗收 → 不像您設計之處逐項回報修正。

## 邊界（Agent 主動提請、由您拍板）

- 元件**不寫死寬度**：您的設計若有固定 px，Agent 會轉相對約束並在報告標註。
- 廣告／追蹤／紅點 streak 等永不實作（AGENTS.md 絕對禁區）。
- 若某設計以「貼近其他品牌」為目的，Agent 會先停問再動。
- 動效涉及功耗／性能取捨時，於完成報告如實說明。

## 建議順序（避免大返工）

1. 先填 `tokens.md`（一份色票＋字型＋圓角＋間距即可，幾分鐘）
2. 再定三個關鍵頁：聊天列表 → 聊天頁 → 圖片預覽
3. 其餘頁面分批補；Agent 依 tokens 自動派生樣式
